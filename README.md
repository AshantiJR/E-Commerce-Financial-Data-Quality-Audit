# E-Commerce Financial Data Quality Audit: Simulated Case Study

## Project Overview

This project is a simulated financial data-quality audit for a fictional e-commerce company. The workbook analyzes 240 order-level records containing sales, refunds, payment activity, product information, fees, taxes, and settlement data.

The purpose of the project was to practice reviewing financial transaction data for accuracy, identifying exceptions, measuring their financial impact, and reconciling expected transaction values to recorded settlement activity.

Rather than beginning with perfectly clean data, the dataset includes realistic exceptions that require review.

## Business Problem

E-commerce financial data can pass through multiple systems before it reaches financial reporting, including order-processing systems, payment platforms, refund activity, and settlement records.

Errors such as duplicate order IDs, missing information, invalid product references, incorrect refund handling, and settlement discrepancies can affect the accuracy of financial records.

The goal of this project was to build a repeatable Excel-based review process that could identify these issues and separate clean transactions from records requiring additional investigation.

## Project Results

The completed audit reviewed 240 simulated e-commerce orders and compared calculated transaction values with recorded settlement activity.

The analysis identified:

- **240** total orders reviewed
- **$15,549.44** in expected net transaction value
- **$15,586.94** in recorded settlement value
- **$37.50** net settlement variance
- **7** orders requiring review
- **2** duplicate-order ID flags
- **1** invalid SKU flag
- **1** missing-required-field flag

Additional exception analysis identified settlement discrepancies requiring investigation while the workbook's control checks verified the underlying order count, expected-net totals, settlement totals, duplicate counts, SKU exceptions, and missing-field counts.

The resulting dashboard provides a centralized view of transaction volume, expected and recorded financial activity, exception counts, settlement variance, and audit-control results.

These controls allow transaction-level problems to be identified while also verifying that summarized audit results agree with the underlying data.
